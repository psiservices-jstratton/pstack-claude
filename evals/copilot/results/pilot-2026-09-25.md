# Copilot build pilot: plain Copilot CLI against Copilot with pstack

Pilot of the blinded A/B harness in [the harness README](../README.md), run on 2026-09-25 with Copilot CLI 1.0.87.

- **Variant under test:** the pstack plugin on the GitHub Copilot CLI (arm B) against the plain Copilot CLI with nothing installed (arm A). Arm B had a pre-written model sheet with every single role on the candidate model and panels of `claude-sonnet-5`, `gpt-5.5`, `gemini-3.8-flash`.
- **Scope:** 1 model (`claude-sonnet-5`), 1 rep, 4 tasks, 2 arms. Judge: `gpt-5.5`, a different family, blinded.
- **Success:** B is at least as correct as A on the hidden checks and better on simplicity, verification evidence, or scope, at an acceptable cost.
- **Rubric (judge only):** correctness, simplicity, verification evidence, scope discipline, each scored 1 to 5, plus which submission the judge would merge.

The pilot ran twice. Run 1 surfaced a real bug in the Copilot build. It was fixed in commit `684ab8d`, and run 2 is the pilot of record.

Copilot bills the user prompt, not the agent's follow-up calls, so pstack's extra work cost wall time, not premium requests.

### Per-task notes (from reading every diff)

- **billing-core.** Both arms made the same root-cause fix: `withPromo` returns a new rule instead of mutating the cached one. B also added a regression test for the cross-customer leak and the repeat promo, plus a two-line comment explaining the cache hazard. A verified with an ad hoc script and the existing suite. Judge preferred B. I agree.
- **contacts-import.** Both arms added the same set-based O(n) dedupe. B's change is smaller (+7) and adds no comment. A added a seven-line comment narrating the optimization. B benchmarked before and after on 50k rows and diffed the kept IDs. A measured only the new speed. Judge preferred B. I agree.
- **partner-clients.** Both arms extracted `src/retry.ts` and kept every client's timing exact (11/11 hidden, including the structural one-loop check). B's helper is a policy object: +46 source lines, against A's callback-heavy helper at +95. B pinned current behavior in a characterization test before refactoring, and afterward it typechecked with `tsc --strict`. For that it ran `npm install --no-save typescript@5` in the project, a side effect that left no tracked change. A rewrote the clients first and added a parity test afterward. Judge preferred B. I agree. B's test file is large (147 lines), but for a behavior-preserving refactor with on-call timing constraints it is in scope.
- **stock-report.** The implementations are nearly identical. B added three CSV tests; A added none and updated the README instead. Judge preferred B for the tests. I call it a narrow B win with one flaw the judge missed: B's `formatCsv` ends with `\r\n`, and `main.ts` appends `\n`, so B's CLI output ends in a blank line. The hidden checks tolerate trailing newlines, so this did not fail. B delegated the implementation to `pstack:poteto-agent` without a `model`, which is equivalent here because the feature role in the sheet named the parent model. It did not read the sheet before dispatching, though.

### Chain-following (from each candidate's `events.jsonl`, not self-report)

- All four B sessions received the routing context from the `SessionStart` hook and loaded `poteto-mode` as their first skill.
- Each read the playbook matching its task: `bug-fix.md`, `perf-issue.md`, `refactoring.md`, and `feature.md`. Three of four read `references/copilot-tools.md`.
- The two sessions whose playbook dispatches on role models read the sheet at the correct absolute path. None ran `setup-pstack`, and none wrote outside its own home.
- No A session loaded a skill. No session in either arm saw eval vocabulary. Arm B installed from a `git archive` export with the harness removed.

## Run 1: `2026-09-25T04-08-49` (surfaced a bug)

Raw outputs: [report.md](2026-09-25T04-08-49/report.md) and siblings.

Same shape and same result: 8/8 hidden checks passed across all runs, and the judge preferred B in 4/4 pairs. In two of four B sessions (contacts-import and partner-clients), the model resolved `COPILOT_HOME`, read the printed directory as a home directory, and appended `.copilot`. It found no sheet there, ran `setup-pstack`, and wrote a second sheet at the wrong path. The harness had named its `COPILOT_HOME` directory `home`, which made the misreading easy, but the prose invited it for any custom `COPILOT_HOME`: it printed a directory and left the model to compose the path. Commit `684ab8d` changes every such instruction to print the sheet's full path and use exactly that path. The harness now mirrors a default install (`COPILOT_HOME` is `$HOME/.copilot`), and the install smoke test still covers a custom `COPILOT_HOME`. Run 2 shows no recurrence.

## Judge compared with my reading

The judge's correctness scores match the hidden checks (all 5s). Its preference for B matches my reading on three of four tasks. On stock-report I would call it closer, because of the trailing blank line. The judge rewards visible tests heavily, and B writes more tests, so part of B's margin is a verification-evidence effect that the rubric intends. The judge did not penalize B's longer wall time, which the rubric does not measure.

## Synthesis

- **No correctness difference.** Both arms passed every hidden check. These fixtures do not separate the arms on correctness for `claude-sonnet-5`, a ceiling effect.
- **Consistent quality edge for B.** B had equal or smaller source diffs (79 against 134 lines), fewer narrating comments, and more durable verification (regression tests, characterization pins, before and after benchmarks). The blinded judge preferred B in 8 of 8 pairs across two runs.
- **Cost.** About 2.2x wall time and 1.8x model calls, at the same premium-request count.
- **Chain-following verified.** The hook, the routing, the playbook choice, and the sheet path all worked from transcripts once the path bug was fixed.
- **Limits.** n=1 per task, one candidate model, one judge, and a small fixture set. This is a pilot, not a measurement.

## Recommendation

**Go for an upstream PR of the Copilot build, conditional on the manual Copilot app check below.** The pilot shows no regression in correctness, a consistent verification and simplicity edge, and a working hook and routing chain on Copilot. It also caught and fixed a real path bug before any user hit it. Do not claim a correctness lift in the PR: this pilot cannot show one. To measure that, rerun with harder fixtures or a weaker candidate model (for example `--models claude-haiku-4.5,gpt-5-mini --reps 3`) before making performance claims.

## Manual Copilot app check

The app loads plugins installed for the Copilot CLI. These steps are not automated.

1. Install into the Copilot home the app uses. Pass the worktree as an absolute path:

   ```shell
   copilot plugin marketplace add /absolute/path/to/pstack-claude
   copilot plugin install pstack@pstack-claude
   ```

   Undo afterward with `copilot plugin uninstall pstack@pstack-claude` and `copilot plugin marketplace remove pstack-claude`.
2. Move any existing `~/.copilot/pstack-models.md` aside so the no-sheet path runs. Restart the app, then open a new session on a scratch repository.
3. Ask: "Without using tools, does your context contain a block that starts with 'You have pstack.' and a paragraph saying this Copilot home has no pstack model sheet yet? Answer yes or no for each." Expect yes and yes. The hook runs at the first message.
4. Ask: "Load the arena skill and tell me its first step; do not run it." Expect the session to run `setup-pstack` first and write `pstack-models.md` in `~/.copilot` (or your `COPILOT_HOME`). The model IDs it writes should come from the `task` tool's list.
5. In a new session, repeat step 3. Expect yes for the mandate and no for the setup line. Then ask it to dispatch `pstack:poteto-agent` with an explicit `model` to answer a one-line question. Expect the dispatch to succeed on that model.
6. Add `session hook: off` to the sheet and open a new session. Repeat step 3. Expect no for both.
7. Remove the `session hook: off` line. Ask the session to use `babysit` on an open PR with a recurring check. Expect it to offer `save_session_automation` instead of a manual cadence. Ask for parallel isolated work, and expect `create_session`.
8. Restore your original sheet, or uninstall as in step 1.
