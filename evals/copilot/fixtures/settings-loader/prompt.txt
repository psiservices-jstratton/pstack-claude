Ops need loadSettings to accept environment overrides for container launches: add an `env` option to `loadSettings(...)` so callers can pass a process-like map, and default to `process.env` when it is omitted. Use the existing `APP_` prefix, use double underscores for nested keys like `APP_DB__PORT`, treat those uppercase variable names case-insensitively, coerce values to the declared schema type, ignore variables for settings not in the schema, and make environment values beat the JSON file; if a number cannot be parsed, throw an error whose message includes the dotted setting name.
