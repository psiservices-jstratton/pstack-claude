On GitHub Copilot, load pstack skills by their bare names through the `skill` tool (`poteto-mode`, `tdd`, `architect`, not `pstack:poteto-mode`); the plugin's agents keep the prefix (`pstack:poteto-agent`, `pstack:comment-sicko`). Copilot lists only part of a large plugin's skills in its prompt; every pstack skill a workflow names still loads by that name. `.github/copilot-instructions.md` and `~/.copilot/copilot-instructions.md` count as user instructions. Resolve every Claude tool, model, path, and built-in skill a pstack skill names through `references/copilot-tools.md` in the `poteto-mode` skill directory. The model sheet is `${COPILOT_HOME:-~/.copilot}/pstack-models.md`, and pstack ships no default Copilot models: before a skill that dispatches on role models (`arena`, `architect`, `interrogate`, `how`, `reflect`, `swarm`, `why`) does anything else, `view` the sheet at the absolute path `bash` prints for `echo "${COPILOT_HOME:-$HOME/.copilot}"` (file tools expand neither `~` nor variables), and if it does not exist load `setup-pstack` with the `skill` tool and finish it first, even for a small question, then reuse its saved choices on later runs.
